# Epoch 5 consolidation: retained ownership and table audit

The target is **53 tables: 35 application tables and 18 Better Auth tables**, down from the audited Epoch 4 source's 96. This document describes the merged baseline from integration parent `774d4c12` and staging parent `3894f251`; the earlier 94-table proposal is superseded. It records physical ownership decisions, not permission to deploy.

The authoritative contracts are [schema.ts](../../server/db/schema.ts), the reviewed source projection in [epoch5-data.mjs](../../scripts/epoch5-data.mjs), [site-transfer-policy.ts](../../shared/site-transfer-policy.ts), and the [cutover procedure](epoch-5-cutover.md). Release actions must follow [release flow](../operations/release-flow.md) and [outage prevention](../operations/release-and-outage-prevention.md). Generate the baseline from Drizzle; do not maintain a parallel handwritten migration.

## Count and source disposition

Forty-eight source table names disappear; five new physical tables replace groups of them: `requests`, `activity_entries`, `analytics_events`, `analytics_summaries`, and `user_workspace_state`. Thus `96 - 48 + 5 = 53`. Existing `sites`, `products`, `business_locations`, `content_documents`, `content_blocks`, `site_domains`, `site_locales`, and `rate_limits` absorb their dependent state.

The projection checks source ownership before folding, preserves provenance in its manifest/archive, and rejects ambiguous mappings. Publication identities replace their former body-only identities; all block references and polymorphic media owners are remapped together. Localized copy is not copied into a second parallel publication model. The production projection's 30 obsolete synthetic Markdown media relationships have explicit per-row evidence; their assets and Markdown content remain. They must not be confused with valid fixture block relationships.

## Application tables retained individually

A foreign key below describes the declared constraint, not an assumption based on a column name. Polymorphic ownership is checked by the named canonical writer and the target invariants. A retention period is stated only where the current implementation supplies one.

| Application table | Actual owner, readers/writers and reason it remains |
| --- | --- |
| `sites` | The tenant identity and transfer root. [Site creation](../../server/utils/site-creation.ts), host resolution and [site transfer](../../server/utils/site-transfer.ts) use its organization, subdomain and team. Scoped children reference it. Fixed owner settings/provider branches use atomic JSON path updates; unrelated branches are not rewritten together. Folding this identity into organization would lose multiple-site ownership. |
| `business_locations` | Actual operating locations, used by [availability](../../server/utils/availability.ts), request scope and public location routes. Same-organization/site FKs distinguish location identity from editorial pages; location hours/timezone and booking configuration now belong here. Team membership stays Better Auth-owned. Multiple locations cannot be represented by a single site setting. |
| `products` | Sellable standard/experience identity, referenced by prices, bookings and product reviews. [Product management](../../server/utils/product-management.ts) and availability use the product type and actual location; experience data is now a native branch. A subtype table no longer exists. |
| `product_categories` | A category is independently ordered and shared by multiple products within a location/product type. [Product management](../../server/utils/product-management.ts), copying and public menus use the referenced category ID. Keeping category identity avoids duplicating category name/order across every product. |
| `prices` | Time-bounded money records with amount/currency/unit constraints and product/location scope FKs. Product pricing queries select the applicable interval; past and future prices are not a single mutable product amount. The validity indexes serve that selection. |
| `offerings` | Professional-service offerings have their own service route, inquiry CTA, schema type and structured service content; [professional services](../../server/utils/professional-services.ts), sitemap and content tools read them. They are referenced media/localization owners, not experience inventory or publication bodies. Location deletion intentionally detaches an offering rather than deleting the site-wide service. |
| `content_documents` | Canonical editorial identity for pages, articles, platform docs, social posts and Q&A. [Content documents](../../server/utils/content-documents.ts) owns updates/deletion. Unique route/slug/root-locale indexes and composite root/site/locale FKs enforce representation identity. Source publication state controls translated public visibility. Provider channels are part of their social owner, not a second queue table. |
| `content_blocks` | Ordered, independently edited and nested content with block IDs used by media and translations. Document/parent FKs and position/source-block indexes preserve hierarchy and source correspondence for every translated block type. Source bindings must reference the matching type in the same canonical root and owner scope. [Block mutations](../../server/utils/content-documents.ts) compare edit tokens; embedding an entire block collection in a document JSON field would remove those referenced identities and independent edits. |
| `resource_localizations` | Non-document resources such as locations, products and offerings still need per-locale field overlays. [Localization](../../server/utils/localization.ts) validates the closed resource registry and actual owner; the site-locale FK and route uniqueness constrain scope. Document translations have moved out, so this table does not duplicate document representations. |
| `site_locales` | The enabled language/entitlement identity that document representations and resource overlays reference through composite FKs. One English source and one published secondary locale are indexed invariants. [Site languages](../../server/utils/site-languages.ts) changes this state; a bundled platform language does not grant publication at a tenant site. |
| `site_redirects` | Historical URL resolution belongs to the old path, even when the current document slug changes. [Redirect middleware](../../server/middleware/zz-redirects.ts) looks up site/locale/path and applies explicit redirect/gone behavior. Folding these rows into current documents would make historical URLs dependent on one live slug and complicate deleted-owner routes. |
| `media_assets` | Provider-backed image/video/file identity, scope and lifecycle, used by uploads, provider cleanup and the media library. [Media asset manager](../../server/utils/media-asset-manager.ts) manages each blob once; several placements can reference it. Asset scope is a composite FK target. |
| `media_placements` | The asset-to-owner/slot/order relationship, independently removable without deleting the blob. Its asset FK enforces same-site scope; the canonical media writer verifies the closed polymorphic owner map atomically. [Media audit](../../scripts/audit-orphaned-media-placements.mjs) checks actual owners. An asset cannot store a single owner when legitimately reused. |
| `customers` | A site-scoped guest identity shared across requests and reviews, with normalized contact uniqueness and optional Better Auth linkage. [Customers](../../server/utils/customers.ts) resolves/deduplicates guests and preserves review opt-out state. This is business customer state, not a shadow authentication identity. |
| `requests` | One aggregate for contact/reservation/experience/platform-contact/work requests and current conversation state. [Request domain](../../server/domain/requests.ts) and guest-thread operations share it. Kind-specific CHECKs enforce booking coordinates, guest/work payloads, state and scope; booking/product/review relationships remain relational. Message history and provider delivery attempts have different cardinality and lifecycles. |
| `activity_entries` | Append-only request/audit/notification facts, read by the shared inbox, notifications and [organization events](../../server/utils/organization-events.ts). Unique request sequence/dedupe and parent FKs preserve ordering and causal links. Site audits use owning `site_id` with CASCADE and no organization FK; original organization is payload provenance. Organization notifications use `context_site_id` with SET NULL. These facts deliberately have different transfer/delete semantics from current requests. |
| `guest_thread_deliveries` | Mutable provider delivery state for a retained activity entry. [Delivery claims](../../server/domain/guest-threads/deliveries.ts) compare status and timestamp, handle provider-specific retry eligibility, and fence outcome writes. Provider-message uniqueness binds callbacks to one delivery. Folding claims/status into immutable activity would mix mutable transport ownership with the original fact; several channels/purposes can deliver one fact. |
| `review_requests` | A signed invitation/token lifecycle tied by composite FK to an actual booking kind/ID. [Review automation](../../server/tasks/review-request-automation.ts) needs expiry, send/reminder state, revocation and customer identity before any review exists. Active-booking uniqueness prevents competing invitations. A review or generic message cannot substitute for this capability. |
| `reviews` | Published/imported/owner-entered review identity, rating and provenance, linked to customers, products and invitations. [Review management](../../server/utils/review-management.ts) and Google sync enforce scoped provider IDs and publication authorization. Ratings, signed submission relationships and provider replies justify a dedicated business record rather than generic editorial metadata. |
| `onboarding_drafts` | Pre-site work owned by a user, with at most one active draft; [onboarding](../../server/utils/onboarding-drafts.ts) commits it to a site and records that transition. It must exist before the site and survive intentional organization/site detachment. It is not an alternate live site. |
| `site_domains` | Globally reserved hostname identity, provider validation/certificate state and durable reconciliation intent. [Domains](../../server/utils/domains.ts) atomically claims a token/deadline and fences provider results; failed deletion remains an explicit desired state. Canonical and active-subdomain indexes prevent conflicting claims. Retired free-domain tombstones outlive the former site so old hostnames cannot be reassigned accidentally. |
| `site_transfer_requests` | A recipient-bound transfer capability with invitation/payment terms, claim identity and pending/accepted lifecycle. [Transfer](../../server/utils/site-transfer.ts) uses the token and compare-and-set transition to authorize atomic reparenting. It cannot be embedded as the site's current owner: invitations exist before acceptance and have their own reminders/payment references. |
| `user_workspace_state` | One application workspace per Better Auth user: selected organization/site/location plus the independent WhatsApp pending-confirmation/inbound state. [MCP context](../../server/utils/mcp-context.ts) patches the relevant branch atomically. It is a preference/workflow cursor, not membership or authorization, and never writes application preferences into Better Auth tables. |
| `public_resource_cache_invalidations` | A transactional outbox row per invalidating write, not a cached site version. [Cache invalidation](../../server/utils/public-resource-cache.ts) claims attempts, retries stale claims, and retains terminal rows for seven days. Folding it into a site flag could lose a second invalidation while an earlier external KV purge completes. |
| `rate_limits` | Atomic expiring counters keyed by request identity, plus the single fixed global Zaraz zone lease. [Hourly limits](../../server/utils/hourly-rate-limit.ts) and [Zaraz](../../server/utils/zaraz-analytics.ts) use count/expiry CAS. The lease spans sites; a per-site lock would permit conflicting writes to the same provider zone. |
| `analytics_events` | Typed raw pageviews/conversions, written by [pageview tracking](../../server/utils/pageview-tracking.ts) and [site conversions](../../server/utils/site-conversions.ts). Conversion identity/attribution and pageview session/visitor indexes support different queries within this one table. Pageview raw retention is 90 days; conversion rows are not removed by that pageview cleanup predicate. |
| `analytics_summaries` | Mutable session and retained day/page/dimension aggregates with unique grain keys, maintained/read by [analytics reporting](../../server/utils/site-analytics-report.ts). These are bounded aggregates rather than duplicate raw events; sessions and daily summaries have the implemented 740-day retention window. Putting them in raw events would mix upserted grains with event identity and retention. |
| `mcp_tool_call_events` | Operational MCP protocol/tool outcomes with redacted argument/result summaries, timing, catalog fingerprints and hashed protocol identities. [MCP telemetry](../../server/utils/mcp-telemetry.ts) writes and admin usage queries read it. SET NULL ownership links preserve diagnostics after owner deletion; this differs from tenant marketing analytics and billing usage. This audit does not invent an unimplemented time-based purge. |
| `organization_billing` | Current access/payment projection, keyed by organization and read by billing/entitlement consumers. [Billing projection](../../server/utils/organization-billing.ts) derives access from provider/payment facts. Stripe customer/subscription identity remains Better Auth-owned; the removed duplicated ID columns do not return. One fast current projection does not replace the underlying invoice/order/usage facts. |
| `stripe_webhook_events` | Provider-event identity, payload and mutable lease/retry/dead-letter lifecycle. [Stripe webhook handling](../../server/utils/better-auth-stripe.ts) fences completion by claim token; [reconciliation](../../server/tasks/stripe-reconciliation.ts) resumes eligible events. Terminal payloads are cleared after 90 days while event identity/state remain for deduplication. This cannot be the immutable usage ledger. |
| `stripe_subscription_versions` | One monotonic event-order watermark per Stripe subscription. [Better Auth Stripe integration](../../server/utils/better-auth-stripe.ts) prevents older events from regressing subscription state. It intentionally has no organization FK: provider ordering must still be known when an event arrives before/after an app ownership record. An invoice or a webhook retry lease has a different key and lifetime. |
| `stripe_invoice_payments` | One invoice payment/period fact with event-order fencing and the GA4 purchase claim/result attached to that invoice. [Stripe integration](../../server/utils/better-auth-stripe.ts) updates ordered invoice state; [GA4 intents](../../server/utils/stripe-ga4-intents.ts) claims purchase delivery. Multiple invoices can affect an organization's access, so the latest organization snapshot cannot replace this identity. |
| `stripe_ga4_subscription_intents` | Short-lived user subscription-change attribution intent, captured before the provider lifecycle event and later matched/consumed. [GA4 intents](../../server/utils/stripe-ga4-intents.ts) expires pending intents and removes consumed records after 90 days. It is neither a paid invoice nor a webhook event; merging them loses the pre-event correlation key and lifecycle. |
| `usage_events` | Immutable, idempotent metered consumption facts with resource/unit/provider attribution. [Usage metering](../../server/utils/usage-metering.ts) and AI credits aggregate these by organization/resource/time. Site links detach while original organization accounting remains. A mutable quota balance or notification record cannot preserve independently deduplicated consumption. |
| `usage_quota_grants` | Independently idempotent grants/adjustments with quantity, resource, unit and period bounds. [Quota adjustment](../../server/utils/quota-adjustment.ts) and metering distinguish granted capacity from consumed usage. Organization retention and grant expiry differ from consumption; a generic activity kind would weaken the dedicated quota transaction/query contract. |

There are **six billing/usage workflow tables beyond `organization_billing`**, seven application tables in that group altogether. The earlier suggestion to fold them into a common provider/usage ledger is rejected by their actual keys, ordering, mutability and retention requirements. Better Auth's `subscription` remains an additional framework-owned table.

## Better Auth ownership

The 18 framework tables are `account`, `invitation`, `jwks`, `member`, `oauthAccessToken`, `oauthClient`, `oauthClientAssertion`, `oauthClientResource`, `oauthConsent`, `oauthRefreshToken`, `oauthResource`, `organization`, `session`, `subscription`, `team`, `teamMember`, `user`, and `verification`.

Their identity/session/OAuth/organization/team contracts are owned by Better Auth and its configured plugins. This consolidation does not relocate application preferences into them, replace membership with a custom scope model, or reinterpret their provider identity fields as application billing facts. The source projection handles the audited framework column-shape corrections explicitly.

## Concurrency and deletion conclusions

- Fixed provider branches are viable inside the site because callbacks compare the relevant provider revision, organization and transfer generation. Public/CMS projections name allowed site fields explicitly; they never serialize `integrations_json`. Transfer clears credentials and invalidates in-flight callbacks atomically.
- Immutable activity remains distinct from mutable delivery claims, webhook claims and quota accounting. Site-audit ownership is relational; original-organization provenance is not a cascading FK that could delete history after transfer.
- Site-owned content/media/customer/booking data follows the explicit transfer table policy. Organization notifications and usage retain their original organization accounting scope. Work-request detachment and owner deletion use the canonical deletion path.
- The retired queued reconciliation row for an already active/valid hostname is not pending work: the old scheduler at `44dc73c2:server/utils/domains.ts` selected only pending/verifying/failed/blocked domains. Its attempt history is archived; no operation payload was lost.

No additional table fold is established by this bounded review as a required correctness fix. The retained outbox, provider delivery state, provider ordering facts and accounting records have concrete independent lifecycles; a lower count alone is not evidence that they share an owner.

## Candidate evidence and pending qualification

The current generated baseline has **53 tables and 826 columns**, with SHA-256 `5076888343c439db5821336e9395fdc56dc02fdf52f2e375bc23f4d8191afc92`. The final merged source projection contains **41,543 rows**, including 110 editorial documents, 679 content blocks and 339 media assets. The checked-in [transfer summary](../../.audit/829-transfer-summary.json) records these aggregate checks, verified at 2026-09-07T00:57:38.607Z.

The external archive retains exact typed records and hashes for all 96 source tables, including the retired database locale catalogs. Thirty obsolete synthetic Markdown media relationships and four obsolete localhost domain rows have explicit private per-row dispositions; retained assets and Markdown content are preserved. Nine translated page blocks acquire relational source IDs from their unique authored field identity and matching source block type within the same page, never from position. The aggregate mapping count and evidence hash are retained in the transfer summary. Four unknown location timezones remain intentionally NULL; those locations have no retained bookings, and availability remains unavailable until an owner supplies the timezone.

These checks qualify the recorded data projection only. The merge incorporates staging's bundled platform catalogs and explicit localization workflow alongside canonical documents and site-locale entitlement. Earlier seed, runtime, browser and CI results describe their recorded pre-merge revisions and do not qualify this merged candidate.
